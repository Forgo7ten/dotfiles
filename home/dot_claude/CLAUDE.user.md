# 用户偏好

## 输出与沟通

- 模型输出使用中文
- 写表述时（代码注释、帮助文案、命名、文档、提交说明等）：直接写当前正确表述即可；不要用「不限 X」「不再是 Y」去强调已删除的旧限制

## 工具使用

- 如果需要使用网页搜索，调用exa MCP，而不是search工具
- 编写 markdown 需要画图时，除非用户特别指明，否则优先使用 mermaid；写完后派 `lite-executor` 调用 `check-mermaid` skill 校验全部 mermaid 代码块，根据其返回的退出码与 JSON 修复，全部通过再交付

## 代码分析

- 如果要分析代码项目（理解架构、查找函数/类、追踪调用链、影响分析、死代码检测等），优先使用 codebase-memory-mcp（先确保项目已索引，用 search_graph / trace_path / get_architecture / detect_changes / query_graph 等结构化查询，而非逐文件 grep+read）

## 子代理使用协议

主代理是编排者：把「宽而重」的只读探索，以及「一个任务内一系列命令、只要结果」的执行外包出去，减少主线程上下文污染；该派就派、宜多派、宜并发。

### 角色

| 角色 | `subagent_type` | 定义 | 用途 |
|------|-----------------|------|------|
| 探子 | `lite-explore` | `~/.claude/agents/lite-explore.md` | 只读探索、检索、核验；返回 `file:line` 证据 |
| 执行器 | `lite-executor` | `~/.claude/agents/lite-executor.md` | 一个执行任务（可含一系列命令/skill），只要结果；返回退出码与输出摘要 |

本段只约定上述两个轻量角色的用法。若角色文件未安装：主代理自跑，或改派当前环境里其他合适的子代理，不要把执行任务硬塞进探子。
**不符合本段场景的工作**（实现、重构、调试、架构、审核等）：由主代理自行判断并选择其他子代理或自己处理，本协议不限制。

### 直接处理（不派）

- 已知位置的小文件、少量代码或单一事实
- 即将修改的具体代码
- **单条**简单命令（主代理直接跑，不必派 `lite-executor`）
- 派发+等待+复核成本不低于自读/自跑的任务
- 奠基性文档（架构/设计/交接等）：无论多长都亲自读；细节与脉络一经转译即失真

### 适合派 `lite-explore`

- 巨型文件（奠基文档除外）、跨文件/跨目录检索
- 相互独立、可并行的探索或核验
- 长任务中需重新确认某模块现状
- 会刷出大量日志、搜索结果或外围材料的阅读

### 适合派 `lite-executor`

- **一个**执行任务：内部可以是一系列命令/脚本，或调用 skill；主代理只要执行结果
- 跑校验 skill/脚本（**mermaid 校验必须走这条**：派 `lite-executor` 调 `check-mermaid`，回收退出码与 JSON）
- 多步但路径已定（如依次检查多个文件、跑测试套件并摘要）、预期长日志只需压缩回传
- 单条简单命令不要派——主代理自己执行

多个独立任务同一轮并发派发；探子与执行器可混派。

### 委派与复核

- 任务必须自包含：范围、问题、期望输出；探索精度场景强制 `file:line` + 符号 + 关键原文；执行场景写明命令/skill、工作目录、成功标准
- 子代理结果是线索；复核 = 顺着出处或退出码/关键输出点验，禁止把已读材料通读一遍或把整段日志贴回主线程（买的是压缩）
- 唯二须主代理完整读原文：① 即将修改的代码 ② 奠基性文档——探子最多定位
- `lite-explore` 只探索/检索/核验；`lite-executor` 只执行并回传结果；改代码、方案取舍、最终验证归主代理

### 派发机制（Claude Code）

- 是否派、派几个由主代理自决，无需用户点名
- 探索用 `lite-explore`，多命令/系列执行用 `lite-executor`（单条命令主代理自跑）；不要把执行塞进探子，也不要把多文件实现塞进 `lite-executor`
- 本段未覆盖的场景：主代理自行选择其他子代理或自行处理
- 每次用新的 `Agent` + 自包含 prompt；不用 `SendMessage` 复用子代理；一轮用完即弃
- 多子代理同一消息并发；发起后停掉其余分析/检索/改文件，**全部返回后再继续**
- 仅在需与其它工作重叠时才 `run_in_background: true`；汇合点收齐再判断
- 同时活跃子代理不超过 6；需要更多时分批派出，上一批返回后再派下一批
- 单子代理约 10 分钟仍未完成：介入，取可用部分，结束盲等；自行决定是否拆小重派

### prompt 最低要求

**lite-explore**

1. 范围（目录/文件/符号）
2. 问题（要/不要回答什么）
3. 输出字段（精度场景强制出处）
4. 停条件（什么叫够了可以返回）

**lite-executor**

1. 要跑的 skill 或命令（完整、可复制）
2. 工作目录 / 输入文件路径
3. 成功标准（如退出码 0、`failed=0`）
4. 需要回传的字段（退出码、JSON 关键键、stderr 头尾等）

子代理看不到主线程历史，勿假设它「猜得到上下文」。

## Git 提交

生成提交信息时使用 Conventional Commits：

```
<type>(<scope可选>): <subject>
```

- `type` 按改动自主判断（如 feat/fix/refactor/chore/docs/perf/test/deps）
- `subject` 简明，概括真实意图
